# 온보딩 페이지 — 설정 및 운영 가이드

띄우는 화면은 **웹페이지 하나**입니다. 진행자는 노션에 붙여넣은 체크리스트를 손에 들고 그 페이지를 위에서 아래로 내려가며 진행합니다.

| 파일 | 누가 보나 | 용도 |
| --- | --- | --- |
| `index.html` | **수강생** | 온보딩 안내 페이지. 화면 공유용이자, 온보딩 이후에도 계속 열어보는 레퍼런스. |
| `온보딩_진행_체크리스트.md` | 운영자 | 노션에 붙여넣어 쓰는 진행 순서표. 세션별 체크리스트와 꼭 해야 하는 멘트만. |
| `SETUP.md` | 운영자 | 이 문서 |

체크리스트의 세션 순서 = 페이지를 스크롤하는 순서입니다. 각 세션의 📺 표시가 그때 보여줄 섹션 이름입니다.

---

## 1. GitHub Pages 배포 (5분)

1. 새 저장소 생성 (예: `ax-onboarding`), **Public**.
2. `index.html` 을 저장소 루트에 업로드.
3. **Settings → Pages** → Source `Deploy from a branch` → Branch `main` / `/ (root)` → **Save**
4. 1~2분 뒤 `https://<계정>.github.io/ax-onboarding/` 에서 열립니다.

**내용을 고칠 때** — GitHub에서 `index.html` 을 열고 연필(✏️) 아이콘 → 수정 → `Commit changes`. 1분 안에 반영됩니다.

---

## 2. 노션에 체크리스트 올리기 (2분)

1. 노션에서 새 페이지 생성.
2. `온보딩_진행_체크리스트.md` 내용을 전부 복사해 붙여넣기.
   - `- [ ]` 는 노션 할 일 목록으로, `>` 는 인용 블록(멘트)으로 자동 변환됩니다.
3. 맨 위 표에 회차 정보와 배포한 페이지 주소를 채웁니다.
4. 회차마다 이 페이지를 **복제**해서 쓰면 체크 상태가 회차별로 남습니다.

---

## 3. 회차마다 바꾸는 것

**수강생 페이지는 손댈 것이 없습니다.** 회차 정보를 넣지 않았기 때문에 그대로 계속 씁니다.

노션 체크리스트를 복제하고 맨 위 표(일자 · 시간 · 형태 · 진행자 · 참석 예정)만 채우면 됩니다.
오프라인으로 진행하는 회차는 문서 아래쪽 **「오프라인 120분으로 진행할 때」** 배치표를 따릅니다.

---

## 4. 당일 운영 순서

1. 화면 공유는 **수강생 페이지 하나만** 띄웁니다.
2. 진행자는 노션 체크리스트를 보며 페이지를 위에서 아래로 스크롤합니다.
3. 세션마다 📺 표시가 가리키는 섹션으로 이동합니다. 순서가 같으므로 한 번 훑으면 그대로 진행됩니다.
4. **출석은 진행자가 직접 확인합니다.** 오프닝에서 사전 명단과 대조해 호명하거나 참가자 목록으로 확인하고, 종료 전에 한 번 더 확인합니다.
5. 미참석자에게는 다음 회차 필수 참석 안내를 발송합니다.

---

## 5. 내용을 계속 채워 나가는 자리

페이지 안에 **점선 박스**로 표시해뒀습니다. 브라우저에서 `Ctrl+F` 로 id를 찾으면 바로 나옵니다.
노션 체크리스트에도 같은 자리가 🔲 로 표시되어 있습니다.

| id | 넣을 내용 |
| --- | --- |
| `slot-outboarding` | 아웃보딩(활동 검토) 기준 — 면담 발생 상황, 절차, 복귀·계약 검토 |

### 회차가 끝날 때마다 해두면 좋은 것

- 반복된 질문 → 페이지 FAQ에 추가
- 새로 접수된 현장 피드백 → **「현장 유의사항」**에 익명화해서 추가
  (고객사명·강사명은 절대 넣지 않습니다. “이런 피드백이 있었습니다 → 그래서 이렇게 해주세요” 형식 유지)
- 시간이 모자라거나 남은 구간 → 체크리스트의 분 배분 조정

노션 체크리스트 맨 아래 **「종료 후 → 회고」**에 같은 항목이 들어 있습니다.
